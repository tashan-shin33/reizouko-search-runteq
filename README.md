## 1. サービス概要

冷蔵庫カタログ内容をデータベース化して欲しい冷蔵庫を迅速に検索するアプリです。  
家電量販店の店員として、個人ユーザーとしてカタログから欲しい冷蔵庫を探すのは面倒です。  
そこでその店の展示冷蔵庫もしくは量販店全体の冷蔵庫の中からユーザーの欲しい冷蔵庫を迅速に見つけ出すサービスです。


## 2. このアイデアはどこから生まれたか

### 2-1. きっかけとなった体験・感情

自分自身が家電量販店で売り場を担当していた時、カタログから確認するのに時間を要することで1日の販売台数に限界があった。

### 2-2. なぜそれが「気になった」のか

メーカーごとにフォーマットが異なりわかりづらく、理想の商品を迅速に案内できなかった。


## 3. 課題の整理（表面的になっていないか）

### 3-1. 表に見えている困りごと

カタログから調べるにはメーカーごとにフォーマットが異なり、わかりづらく、また既存の検索システムもわかりづらく操作しにくい。

### 3-2. 本当に解決したい課題は何か

なぜ時間がかかるのか？  
→ カタログの情報量が多く、目的の情報にたどり着きにくい。  

なぜそれが問題なのか？  
→ 本当にそのお客様にとって、理想ではない買い物につながる。

なぜそれが困るのか？  
→ 顧客満足度の低下や販売機会の損失につながる  

本当に解決したい課題：  
　PC操作に慣れない人でも短時間で最適な商品提案ができる状態を作ること


## 4. 想定ユーザーについて

年齢設定：
- 年齢：30〜60代
- 理由：冷蔵庫の買い替えを検討する層が多く、比較検討を重視するため

生活・状況：
- 設置環境、お客様の全ての要望を満たす冷蔵庫に買い替えたいと考えている

環境：
- 家電量販店の店頭
 　家電量販店で販売している冷蔵庫の中から検索する端末を店に設置する

本サービスは「購入を検討している一般ユーザー（特にシニア層）」向けのtoCサービスとする。

理由としては、もともとの課題である「カタログが分かりづらく、目的の商品にたどり着きにくい」という問題は、
店員だけでなく購入者自身にも当てはまると考えたためです。

特にシニア層は、
・検索サービスの操作が難しい  
・情報量が多いと判断が難しい  
といった課題があるため、

「入力項目を最小限にし、直感的に操作できる検索体験」を提供することで、
自身で商品を選べる状態を作ることを目的としました。

そのため、本サービスでは在庫管理や店舗連携などの機能は持たせず、
あくまで「商品選定の補助」に特化したサービスとして設計しています。


## 5. 既存サービス・競合調査

### 5-1. 似たサービスの調査

価格.com  
いろんな検索できるが操作が複雑で入力する項目が多すぎて、年配の方は使えない。  
入力項目が多く、目的の条件にたどり着くまでに時間がかかる

### 5-2. それでも自分が作りたい理由、差別化

接客経験を通して、お客様が本当に知りたいことはそんなに多くはなく、  
シンプルで簡単に検索できることが必要と考えています。  
誰でも操作でき、選択できる項目を必要最小限にする。


## 6. このサービスで提供したい価値

知りたいことだけシンプルに検索して、速やかに知りたい情報を得ることができる。


## 7. このアプリで実現すること

お客様が知りたい情報だけを即座にゲットできる。

### データベース構築について

本アプリでは、冷蔵庫のカタログ情報をデータベース化するにあたり、以下の方法を検討しています。

- 初期データは主要メーカーの公式サイトやカタログ情報をもとに手動で登録する
- MVP段階では、対象メーカーや機種を限定し、最小限のデータで検証を行う
- 将来的には、CSVインポート機能の実装や外部APIの活用により、データ登録の効率化を検討する
- テーブル作成の際、編集日付を追加し、定めた期限を過ぎたデータを定期的に削除していきます

また、新製品の追加や更新については、定期的にデータを更新できる仕組みを検討し、運用面での負担を軽減することを目指します。

外部APIについては現時点で適切なものは見つかっていないため、MVP段階では手動登録で対応します。  
将来的にはCSVインポート機能やメーカー連携を検討します。

データ削除については、古い製品情報が残ることで検索精度低下や誤案内につながります。  
常に最新に近い情報を保つことを目指します。

そのため、運用としては以下の方針を想定しています。

・データは削除せず「販売終了フラグ」を持たせる  
・検索結果には「販売中の商品」のみ表示する  
・必要に応じて「販売終了商品も表示」などの切り替えを検討する  
　また、ユーザーに対しては
　「販売終了商品は通常表示されません」といった説明をUI上に記載し、混乱を防ぐ設計にします。

これにより、
・過去に見た商品が消える問題の回避  
・検索結果の精度維持  
の両立を目指します。

### 利用イメージ（操作フロー）

本サービスは、店員が接客中にタブレット端末などで操作することを想定しています。

- 1画面に2〜4項目程度の入力欄を配置
- 数値入力またはプルダウンで選択
- 条件入力後、候補一覧を表示
- 条件を追加して絞り込み

直感的に操作できるシンプルなUIを目指します。

### MVPで作る機能

- データ登録（手動）
- 条件検索
- 一覧表示

### 本リリースで作る機能

- 詳細検索
- CSVインポート
- UI改善
- データ自動更新・削除

## 10. 技術スタック（手段としての技術）

### 10-1. 使用予定の技術

- フレームワーク：Ruby on Rails
- DB：PostgreSQL
- デプロイ先：Render
- 使用予定ライブラリ：Ransack / Devise

### 10-2. 技術選定の理由

- なぜこの技術を使うのか  
Railsは学習してきた技術であり、効率よくWebアプリを開発できるため。

- 今回チャレンジしたい点  
検索機能の強化や、複数条件でのデータ抽出を実装したい。

- 不安な点  
検索処理のパフォーマンスや、データ設計が適切にできるか不安がある。
