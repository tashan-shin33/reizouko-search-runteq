## 1. サービス概要
　冷蔵庫カタログ内容をデータベース化して欲しい冷蔵庫を迅速に検索するアプリです。
　家電量販店の店員として　個人ユーザーとしてカタログから欲しい冷蔵庫を探すのは面倒です。
　そこでその店の展示冷蔵庫もしくは業界全体の冷蔵庫の中からユーザーの欲しい冷蔵庫を迅速に見つけ出すサービスです。


## 2. このアイデアはどこから生まれたか
　### 2-1. きっかけとなった体験・感情
　　自分自身が家電量販店で売り場を担当していた時、カタログから確認するのに時間を要することで１日の販売台数に限界があった。
　### 2-2. なぜそれが「気になった」のか
　　お客様の要望にピッタリあった理想の商品を迅速に案内するのが店員の責務であり、それを迅速にできないか気になりました。


## 3. 課題の整理（表面的になっていないか）
　### 3-1. 表に見えている困りごと
　　お客様と一緒にカタログから調べるのに時間がかかり、次のお客様の接客に移れない。
　### 3-2. 本当に解決したい課題は何か
   なぜ時間がかかるのか？
    → カタログの情報量が多く、目的の情報にたどり着きにくい

   なぜそれが問題なのか？
    → 接客中にお客様を待たせてしまう
  
   なぜそれが困るのか？
    → 顧客満足度の低下や販売機会の損失につながる

  本当に解決したい課題 ： 接客中でも短時間で最適な商品提案ができる状態を作ること 

  
## 4. 想定ユーザーについて
　　年齢設定：
    - 年齢：30〜60代
    - 理由：冷蔵庫の買い替えを検討する層が多く、比較検討を重視するため

   生活・状況：
    - 家族で使用する冷蔵庫を買い替えたいと考えている
    - 店頭で店員に相談しながら商品を選びたい

   環境：
    - 家電量販店の店頭
    - 店員と対話しながら商品を検討する
    
　　店員が在庫等を調べるために持ち歩いている端末に商品検索をする機能をつける
　　家電量販店で販売している冷蔵庫の中から検索する端末を店に設置する


## 5. 既存サービス・競合調査
　### 5-1. 似たサービスの調査
　　価格.com
　　いろんな検索できるが操作が複雑で入力する項目が多すぎて、年配の方は使えない。
    入力項目が多く、目的の条件にたどり着くまでに時間がかかる
 ### 5-2. それでも自分が作りたい理由、差別化
　　接客経験を通して、お客様が本当に知りたいことはそんなに多くはなく
  　シンプルで簡単に検索できることが必要と考えています。
　　 誰でも操作でき、選択できる項目を必要最小限にする。


## 6. このサービスで提供したい価値
　　知りたいことだけシンプルに検索して、速やかに知りたい情報を得ることができる。


## 7. このアプリで実現すること
　　お客様が知りたい情報だけを即座にゲットできる。
  

## 8. このアプリの懸念点とその対策
　　お客様が予期しない質問を投げられた時に即座に対応できないという問題に対し
    機能を即座にアップできるように保守性の向上を考えて設計する。
    

## 9. 今後の展開・発展の方向性
　　今回は設計の方向性の決定、使いやすさの追求を決めるため試験的に冷蔵庫だけの検索アプリを
  　作成するが、仕様が固まれば、他の製品にも展開していく。

    
## 10. 技術スタック（手段としての技術）
　### 10-1. 使用予定の技術
　　- フレームワーク： Ruby on Rails
   - DB： PostgreSQL
   - デプロイ先：Render
   - 使用予定ライブラリ：Ransack（検索機能）　Devise（ログイン機能）
　### 10-2. 技術選定の理由
　　- なぜこの技術を使うのか  
　　　Railsは学習してきた技術であり、効率よくWebアプリを開発できるため。
　　- 今回チャレンジしたい点  
　　　検索機能の強化や、複数条件でのデータ抽出を実装したい。
　　- 不安な点
　　　検索処理のパフォーマンスや、データ設計が適切にできるか不安がある。
